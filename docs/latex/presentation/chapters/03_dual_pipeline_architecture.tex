% Chapter 3: The Asymmetric Dual-Pipeline Paradigm

\begin{frame}{Core Architecture}{Decoupling Representation from Reasoning}
    \begin{block}{Slide Topic \& Explanatory Focus}
        This slide introduces the overarching architectural paradigm of TaxonVision: the asymmetric dual-pipeline decoupled architecture.
        \begin{itemize}
            \item \textbf{The Monolithic Trap:} Junior practitioners often attempt to train an end-to-end convolutional or vision transformer network that directly outputs species logits.
            \item \textbf{The Retraining Bottleneck:} When new species are discovered or taxonomic revisions occur, an entire multi-gigabyte backbone must be painfully retrained.
            \item \textbf{The Decoupled Solution:} TaxonVision cleanly decouples static visual representation (Pipeline 1) from dynamic taxonomic reasoning (Pipeline 2).
            \item \textbf{Agile Outcomes:} This separation enables agile, localized updates and sub-second classification without full retraining loops.
        \end{itemize}
    \end{block}

    \vspace{0.4cm}
    \statusdone

    \script{This slide represents the core architectural breakthrough of our system: the Asymmetric Dual-Pipeline. In naïve computer vision, you take an image, pass it through ResNet, and output 1,000 class probabilities. But in biology, taxonomy changes every month: species are split, renamed, or reclassified. If you use a monolithic model, every single rename forces a full 10-hour retraining run on expensive GPUs. By decoupling representation from reasoning, our foundation model stays entirely frozen while our taxonomic knowledge graph updates in real time with zero mathematical friction.}
    \qa{What is a foundation model in this context?}{A massive vision transformer, such as BioCLIP or DINOv2, pre-trained on hundreds of millions of biological images using self-supervised learning. It produces rich semantic feature vectors that capture fine-grained morphological details without requiring task-specific retraining.}
    \qa{Why "Asymmetric"?}{Because the pipelines operate at vastly different timescales and compute intensities. Pipeline 1 involves dense matrix multiplications on GPUs, while Pipeline 2 involves lightweight graph traversals and vector lookups on CPUs.}
\end{frame}

\begin{frame}{Pipeline 1}{Offline Representation \& Linear Probe Training}
    \begin{block}{Slide Topic \& Explanatory Focus}
        This slide details Pipeline 1: the offline representation and classification workflow.
        \begin{itemize}
            \item \textbf{S3 Batch Streaming:} High-resolution raw images stored in remote S3 are processed in batch streams.
            \item \textbf{Frozen Backbone Inference:} Images pass through frozen backbones (DINOv2, BioCLIP) to generate dense feature embeddings (768 or 1024 dimensions).
            \item \textbf{Serialization:} These embeddings are serialized into content-addressable storage (Parquet/DVC).
            \item \textbf{Linear Probing:} Downstream, lightweight linear classifiers are trained using Class-Balanced Loss and Bayesian hyperparameter sweeps (Optuna).
            \item \textbf{ONNX Export:} The final heads are compiled into ONNX-quantized models ready for high-throughput serving.
        \end{itemize}
    \end{block}

    \vspace{0.4cm}
    \statusdone

    \script{Pipeline 1 is our offline training engine. Instead of feeding raw images directly into training loops every epoch, we pass them through our frozen backbone once and store the resulting numerical embeddings on disk. Once those embeddings are saved, training a new classification head takes literally ten seconds. We can run 50 hyperparameter optimization trials with Optuna in five minutes on a single GPU—something that would take days with full end-to-end fine-tuning. This is how we achieve extreme ML operational efficiency.}
    \qa{Does training only a linear head hurt classification accuracy compared to full fine-tuning?}{Empirical benchmarks show that modern self-supervised backbones like DINOv2 and BioCLIP produce representations so rich that linear probes achieve within 1 to 2 percent of full fine-tuning accuracy. The massive savings in compute cost and the elimination of catastrophic forgetting far outweigh this marginal trade-off.}
    \qa{What is Class-Balanced Loss?}{A loss function weighting technique that corrects for the long-tail distribution typical in biological datasets, ensuring rare species are not ignored by the model in favor of common ones.}
\end{frame}

\begin{frame}{Pipeline 2}{Taxonomic Multimodal Knowledge Graph (MMKG)}
    \begin{block}{Slide Topic \& Explanatory Focus}
        This slide explains Pipeline 2: the continuous taxonomic ingestion and Multimodal Knowledge Graph (MMKG) streaming pipeline.
        \begin{itemize}
            \item \textbf{Hierarchical Taxonomy:} Biological classifications form an 8-level tree (Kingdom to Species).
            \item \textbf{DarwinCore Ingestion:} Pipeline 2 continuously ingests DarwinCore metadata streams to update taxonomic relations.
            \item \textbf{Graph Construction:} It builds a directed acyclic graph (DAG) of biological lineage in a graph database.
            \item \textbf{Vector Indexing:} Multimodal embeddings are indexed via HNSW into a vector database, linked directly to graph nodes.
            \item \textbf{Vision-RAG Fallback:} When visual ambiguity arises, the system performs Vision-RAG (Retrieval-Augmented Generation) against verified exemplar specimens to resolve close morphological ties.
        \end{itemize}
    \end{block}

    \vspace{0.4cm}
    \statustarget

    \script{While Pipeline 1 provides raw computational classification, Pipeline 2 provides actual biological wisdom. Taxonomy is not a flat list of labels; it is an evolving phylogenetic tree. Pipeline 2 stores this tree in a Multimodal Knowledge Graph. If the classifier is mathematically uncertain whether a specimen is Species A or Species B, Pipeline 2 queries their taxonomic relations, habitat metadata, and anatomical descriptions—acting exactly like a human field botanist cross-referencing herbarium records in real-time.}
    \qa{How does the vector database fit into the knowledge graph?}{Each taxonomic node is linked to reference exemplar embeddings in our vector store. This allows us to perform nearest-neighbor visual similarity searches constrained entirely within specific sub-branches of the taxonomic tree, vastly reducing search space.}
    \qa{What does DarwinCore ingestion provide?}{DarwinCore is the global standard for biodiversity data. It provides the standardized metadata—such as geographic coordinates, collector information, and accepted scientific names—required to construct the taxonomic graph accurately.}
\end{frame}

\begin{frame}{Inference Serving}{Serving Boundary Convergence \& Fast-Path Routing}
    \begin{block}{Slide Topic \& Explanatory Focus}
        This slide examines the runtime convergence point where Pipeline 1 and Pipeline 2 meet to serve live inference requests under strict latency budgets (p95 $< 50$ ms).
        \begin{itemize}
            \item \textbf{FastAPI Ingress:} An image upload hits the FastAPI endpoint and immediately enters the Fast-Path.
            \item \textbf{Sub-15ms Execution:} ONNX Runtime evaluates the quantized linear probe and computes conformal uncertainty sets in $< 15$ ms.
            \item \textbf{Singleton Fast-Return:} If conformal coverage produces a high-confidence singleton set, the result returns immediately.
            \item \textbf{Asynchronous Enrichment:} Only ambiguous predictions (multi-class sets) or out-of-distribution observations trigger deep enrichment from Pipeline 2's knowledge graph.
        \end{itemize}
    \end{block}

    \vspace{0.4cm}
    \statusdone

    \script{In production APIs, speed is everything. We simply cannot afford to query a complex graph database on every single simple request. We implement a Fast-Path serving boundary: the incoming image runs through our ultra-fast ONNX model. If the prediction is unambiguous—meaning the conformal predictor returns exactly one class—the API responds in under 15 milliseconds. Only when the model mathematically detects ambiguity does it trigger the deep, slightly slower, taxonomic enrichment pipeline.}
    \qa{What is ONNX Runtime and why do we use it instead of native PyTorch?}{ONNX Runtime optimizes the computation graph, fuses operations, and performs strict memory reuse. It eliminates Python interpreter overhead, resulting in 2x to 4x lower latency and rigorously enforces zero memory allocations on the hot inference path.}
    \qa{What is conformal uncertainty?}{It is a mathematically rigorous framework that outputs a set of possible classes rather than a single point prediction, guaranteeing with a user-specified probability (e.g., 95\%) that the true class is contained within that set.}
\end{frame}
