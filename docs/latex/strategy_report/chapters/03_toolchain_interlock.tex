\chapter{Open-Source MLOps Toolchain}
\label{ch:toolchain}

In order to construct a production-grade machine learning platform without incurring prohibitive enterprise cloud licensing costs, our architecture integrates a curated selection of open-source components. However, merely assembling disparate tools is insufficient. True operational resilience requires a deep, mechanical interlocking between data versioning, experiment telemetry, and hyperparameter optimisation.

\section{Content-Addressable Storage and Cryptographic Versioning}
\label{sec:dvc}

Standard version control systems, such as Git, are engineered to track line-by-line code modifications within directed acyclic graphs of text files. Applying this paradigm to binary biological datasets is architecturally catastrophic. Committing a 50-gigabyte archive of high-resolution images forces the repository database to duplicate entire assets upon the slightest modification. This inevitably leads to memory exhaustion and repository collapse.

The system safely circumvents this limitation by utilising Data Version Control (DVC), which implements content-addressable storage. Rather than tracking the physical image matrices, DVC computes a unique SHA-256 cryptographic hash based strictly on the pixel content of the target directory. The heavy binary payloads are routed directly to a remote storage bucket, while a lightweight pointer file (for example, \texttt{dataset.dvc}) containing only the resultant hash and file metadata is generated.

This pointer file is subsequently committed to Git. When a deployment runner or data scientist executes a checkout command for a specific historical commit, the DVC client reads the hash from the pointer file, resolves the asset location in the remote cache, and constructs near-instantaneous filesystem reflinks (or hardlinks) into the local workspace. This dual-layered approach reliably decouples the heavy binary storage from the codebase, whilst guaranteeing mathematically verifiable, bit-for-bit data reproducibility.

\section{Unified Management Plane}
\label{sec:dagshub}

Operating a distributed MLOps toolchain traditionally requires provisioning disparate enterprise infrastructure: an external PostgreSQL database cluster for experiment telemetry, dedicated S3 storage buckets, and complex Identity and Access Management (IAM) matrices to broker inter-service communication.

For a single-host k3s deployment, running an enterprise-scale PostgreSQL server introduces an unjustifiable persistent memory footprint of 1.0 to 2.0~GB RAM. The architecture eliminates this overhead by deploying an embedded MLflow tracking backend powered by SQLite configured in Write-Ahead Logging (\texttt{WAL}) mode. Operating with an active memory footprint of approximately 15~MB, SQLite WAL guarantees full ACID transaction isolation and robust multi-process concurrency on NVMe storage. Heavy binary artefacts are offloaded directly to the local MinIO object store (\texttt{s3://taxon-lakehouse/}) or mirrored to DagsHub, establishing a zero-maintenance telemetry plane with zero public cloud egress charges.

\section{Bayesian Hyperparameter Optimisation and Telemetry}
\label{sec:hyperparameter_opt}

Model convergence, latency minimisation, and epistemic reliability depend fundamentally on tuning discrete and continuous training hyperparameters. Rather than viewing hyperparameter configuration and experiment tracking as disjoint manual procedures, the architecture integrates Bayesian optimisation algorithms directly with distributed metric logging pipelines in order to form a self-contained optimisation loop.

\subsection{Intelligent Search Mechanics}

Neural network architectures require the optimisation of external hyperparameters, such as learning rates, weight decay penalties, and conformal confidence thresholds. Traditional Grid Search algorithms evaluate these spaces exhaustively, incurring a computational cost of $\mathcal{O}(S^D)$, where $S$ represents the number of discrete steps evaluated across $D$ hyperparameter dimensions. On a single-node bare-metal architecture, this geometric explosion renders hyperparameter tuning computationally unviable.

The platform replaces brute-force evaluation with Optuna, driven by the Tree-structured Parzen Estimator (TPE). TPE abandons blind search grids in favour of Bayesian conditional density modelling. Let $y$ denote the objective validation Macro PR-AUC metric to be maximised, and let $y^*$ represent a dynamically evaluated scalar quantile threshold separating the upper quantile of top-performing trials from the baseline distribution. TPE models the conditional parameter probability distribution $p(\theta \mid y)$ directly as
\[
p(\theta \mid y) = 
\begin{cases} 
    \ell(\theta) & \text{if } y \ge y^*, \\ 
    g(\theta) & \text{if } y < y^*,
\end{cases}
\]
where $\theta$ denotes the evaluated hyperparameter vector, $\ell(\theta)$ is the non-parametric probability density function constructed over the parameter configurations of superior historical trials ($y \ge y^*$), and $g(\theta)$ represents the density function constructed over sub-optimal evaluations ($y < y^*$).

The acquisition algorithm iteratively samples candidate configurations that maximise the density ratio $\ell(\theta) / g(\theta)$. This guides the GPU to evaluate parameter domains mathematically correlated with elevated classification precision on long-tail taxa, whilst maintaining sufficient dispersion to escape local extrema.

In order to conserve hardware cycles, Optuna applies the Asynchronous Successive Halving Algorithm (ASHA) with a minimum resource allocation of two epochs and a reduction factor of $\eta = 2$. A trial is first evaluated after two epochs; at each subsequent rung, only the superior half of the candidate configurations ($1/\eta$) is permitted to proceed, whilst inferior trajectories are terminated immediately.

To guarantee continuity across iterative training cycles and prevent redundant evaluations, Optuna studies are backed by persistent SQLite storage (\nolinkurl{sqlite:///data/optuna_studies.db}) with study identifiers scoped deterministically by vision backbone (for example, \texttt{tuning\_dinov3} or \texttt{tuning\_bioclip2}) under \texttt{load\_if\_exists=True}. This persistence layer enables subsequent tuning invocations to warm-start from prior historical parameter trials, progressively refining the non-parametric Parzen density estimates without discarding previous evaluations.

\subsection{MLflow Interlock Architecture}

While Optuna efficiently orchestrates the search mathematics, it inherently lacks the infrastructure to permanently archive model provenance across a distributed engineering team. MLflow bridges this gap, operating as the continuous flight data recorder for our training pipeline.

The integration is implemented directly within the objective function. The tuning session registers as an MLflow experiment on the tracking server, and each trial is executed within a nested child run. To avoid socket starvation and excessive network I/O during rapid hyperparameter sweeps, all epoch metrics -- training loss, validation loss, Top-1 accuracy, Macro F1-score, and validation Macro PR-AUC -- are aggregated in memory and submitted at trial completion or ASHA pruning using \texttt{MlflowClient().log\_batch()}. The lifecycle of the primary run is governed by a deterministic context manager, guaranteeing that unexpected execution exceptions transition the run to a \texttt{FAILED} state rather than hanging perpetually.

Model promotion evaluates candidate Macro PR-AUC against the incumbent holding the \texttt{Production} alias in the MLflow Model Registry. Qualified candidates receive the alias \texttt{Challenger} pending automated deployment verification. During registry registration, an explicit \texttt{ModelSignature} is inferred directly from genuine validation batch tensors (\texttt{val\_embeddings}) via \texttt{infer\_signature()}, completely eliminating synthetic tensor mocks and guaranteeing type-safe schema enforcement. The model version entry is enriched with immutable audit metadata, including the vision backbone tag, empirical validation Macro PR-AUC score, and human-readable architecture descriptions.

Crucially, every training execution renders and logs publication-grade evaluation artifacts directly into the MLflow run:
\begin{enumerate}
    \item \nolinkurl{visualizations/confusion_matrix.png}: A class-normalized confusion matrix validating individual taxonomic boundaries.
    \item \nolinkurl{visualizations/precision_recall_curves.png}: Per-class Precision-Recall trajectories annotated with individual Average Precision (AP) scores across all catalogued taxa.
    \item \nolinkurl{visualizations/energy_distribution.png}: The empirical validation Helmholtz free-energy distribution annotated with the calibrated epistemic decision boundary $\tau_{\text{OOD}}$.
\end{enumerate}
When hyperparameter tuning is triggered, diagnostic Optuna plots (\nolinkurl{optuna_optimization_history.png} and \nolinkurl{optuna_param_importances.png}) are synchronously attached. Furthermore, the calibrated Conformal Prediction thresholds (\nolinkurl{config/conformal_config.yaml}) are packaged directly into the model directory, guaranteeing atomic deployments of neural weights alongside their epistemic safety parameters.

\section{Training Dynamics and Convergence Control}
\label{sec:training_dynamics}

Because the backbone is frozen and its embeddings are cached, a training epoch of the classification head reduces to a small number of matrix products. The principal risk is therefore not under-fitting but over-fitting to the rare classes of the long tail. Three mechanisms control this risk. All of them monitor the validation Macro PR-AUC, which is also the promotion metric of the registry:
\begin{enumerate}
    \item \textbf{Best-weight restoration:} The head weights of the epoch with the highest validation Macro PR-AUC are cached and restored once training has ended, so that the returned head is the best head and not merely the last one.
    \item \textbf{Early stopping:} Training terminates when the metric has not improved for four consecutive epochs.
    \item \textbf{Learning-rate reduction on plateau:} The learning rate is halved when the metric has not improved for two epochs. Since this patience is shorter than that of early stopping, the optimiser receives at least one epoch at a reduced rate before training terminates.
\end{enumerate}

As design defaults, the epoch budget is limited to 15 epochs and the mini-batch size is 64 for training on cached embeddings. Where embeddings are extracted from images by a Vision Transformer on the GPU, a smaller batch of 32 images keeps the activation memory comfortably inside the budget of Section~\ref{sec:gpu_partitioning}. The feature extraction pipeline (\texttt{taxon\_vision.pipelines.extract\_features}) extracts these representations directly from AWS S3, caching them to disk for subsequent head convergence (see Section~\ref{sec:impl_status}).

Data augmentation applied during embedding extraction must respect biological invariants. Horizontal reflection yields physically plausible specimens, because most organisms are bilaterally or radially symmetric about a vertical axis. Vertical reflection is prohibited: gravity and phototropism impose a canonical orientation, so that an inverted specimen would never occur in field imagery and would merely bias the learned spatial priors.
