\chapter{Open-Source MLOps Toolchain}
\label{ch:toolchain}

In order to construct a production-grade machine learning platform without incurring prohibitive enterprise cloud licensing costs, our architecture integrates a curated selection of open-source components. However, merely assembling disparate tools is insufficient. True operational resilience requires a deep, mechanical interlocking between data versioning, experiment telemetry, and hyperparameter optimisation.

\section{Content-Addressable Storage and Cryptographic Versioning}
\label{sec:dvc}

Standard version control systems, such as Git, are engineered to track line-by-line code modifications within directed acyclic graphs of text files. Applying this paradigm to binary biological datasets is fundamentally unsuitable. Committing a 50-gigabyte archive of high-resolution images forces the repository database to duplicate entire assets upon the slightest modification. This inevitably leads to memory exhaustion and repository collapse.

The system safely circumvents this limitation by utilising Data Version Control (DVC), which implements content-addressable storage. Rather than tracking the physical image matrices, DVC computes a unique SHA-256 cryptographic hash based strictly on the pixel content of the target directory. The heavy binary payloads are routed directly to a remote storage bucket, whilst a lightweight pointer file (for example, \texttt{dataset.dvc}) containing only the resultant hash and file metadata is generated.

This pointer file is subsequently committed to Git. When a deployment runner or data scientist executes a checkout command for a specific historical commit, the DVC client reads the hash from the pointer file, resolves the asset location in the remote cache, and constructs near-instantaneous filesystem reflinks (or hardlinks) into the local workspace. This dual-layered approach reliably decouples the heavy binary storage from the codebase, whilst guaranteeing mathematically verifiable, bit-for-bit data reproducibility.

To ensure non-blocking, rate-compliant upstream data acquisition from public biological APIs (such as iNaturalist and GBIF), ingestion workers enforce strict concurrency controls. API queries are mediated by an asynchronous token-bucket rate limiter (\texttt{aiolimiter.AsyncLimiter(1.0, 1.0)}), guaranteeing compliance with upstream throughput ceilings (maximum 1 request per second). Concurrent disk writes and manifest mutations across parallel workers are protected by POSIX advisory file locking via \texttt{filelock}, completely eliminating race conditions and corrupted Parquet manifests during multi-threaded data ingestion.

\section{Unified Management Plane}
\label{sec:dagshub}

Operating a distributed MLOps toolchain traditionally requires provisioning disparate enterprise infrastructure: an external PostgreSQL database cluster for experiment telemetry, dedicated S3 storage buckets, and complex Identity and Access Management (IAM) matrices to broker inter-service communication.

To eliminate cloud egress fees and maintain complete sovereign control over telemetry, the platform consolidates tracking and versioning into an in-cluster control plane. Telemetry and experiment metadata are anchored in the self-hosted \textbf{PostgreSQL 16} cluster within the dedicated \texttt{mlflow} database, operating with an active footprint of under 80~MB RAM. Heavy binary model checkpoints and evaluation artefacts are managed by a self-hosted MLflow 3.x tracking proxy server (\texttt{ghcr.io/mlflow/mlflow:v3.16.0}) executing with \texttt{--serve-artifacts} backed by the in-cluster SeaweedFS Apache 2.0 object store (\texttt{s3://mlflow-artifacts/}). DagsHub acts as an external Git and DVC synchronisation mirror and hosted Label Studio workspace, while SQLite WAL persistence is retained strictly as an automatic fallback for offline workstation iteration.

\section{Bayesian Hyperparameter Optimisation and Telemetry}
\label{sec:hyperparameter_opt}

Model convergence, latency minimisation, and epistemic reliability depend fundamentally on tuning discrete and continuous training hyperparameters. Rather than viewing hyperparameter configuration and experiment tracking as disjoint manual procedures, the architecture integrates Bayesian optimisation algorithms directly with distributed metric logging pipelines in order to form a self-contained optimisation loop.

\subsection{Intelligent Search Mechanics}

Neural network architectures require the optimisation of external hyperparameters, such as learning rates, weight decay penalties, and conformal confidence thresholds. Traditional Grid Search algorithms evaluate these spaces exhaustively, incurring a computational cost of $\mathcal{O}(S^D)$, where $S$ represents the number of discrete steps evaluated across $D$ hyperparameter dimensions. On a single-node bare-metal architecture, this geometric explosion renders hyperparameter tuning computationally unviable.

The platform replaces brute-force evaluation with Optuna, driven by the Tree-structured Parzen Estimator (TPE). TPE abandons blind search grids in favour of Bayesian conditional density modelling. Let $y$ denote the objective validation Macro PR-AUC metric to be maximised, and let $y^*$ represent a dynamically evaluated scalar quantile threshold separating the upper quantile of top-performing trials from the baseline distribution. TPE models the conditional parameter probability distribution $p(\theta \mid y)$ directly as
\[
p(\theta \mid y) = 
\begin{cases} 
    \ell(\theta) & \text{if } y \ge y^*, \\ 
    g(\theta) & \text{if } y < y^*,
\end{cases}
\]
where $\theta$ denotes the evaluated hyperparameter vector, $\ell(\theta)$ is the non-parametric probability density function constructed over the parameter configurations of superior historical trials ($y \ge y^*$), and $g(\theta)$ represents the density function constructed over sub-optimal evaluations ($y < y^*$).

The acquisition algorithm iteratively samples candidate configurations that maximise the density ratio $\ell(\theta) / g(\theta)$. This guides the GPU to evaluate parameter domains mathematically correlated with elevated classification precision on long-tail taxa, whilst maintaining sufficient dispersion to escape local extrema.

In order to conserve hardware cycles, Optuna applies the Asynchronous Successive Halving Algorithm (ASHA) with a minimum resource allocation of three epochs and a reduction factor of $\eta = 2$. A trial is first evaluated after three epochs; at each subsequent rung, only the superior half of the candidate configurations ($1/\eta$) is permitted to proceed, whilst inferior trajectories are terminated immediately.

To guarantee continuity across iterative training cycles and prevent redundant evaluations, Optuna studies are backed by persistent PostgreSQL storage (\nolinkurl{postgresql+psycopg2://optuna:...@postgres:5432/optuna}) with study identifiers scoped deterministically by vision backbone (for example, \texttt{tuning\_dinov3} or \texttt{tuning\_bioclip2}) under \texttt{load\_if\_exists=True}. SQLite storage (\nolinkurl{sqlite:///data/optuna/optuna_studies.db}) is retained strictly as an automatic fallback for offline development. This persistence layer enables subsequent tuning invocations to warm-start from prior historical parameter trials, progressively refining the non-parametric Parzen density estimates without discarding previous evaluations.

\subsubsection{Effective Sample Weighting and the Non-Saturating Dynamics of \texorpdfstring{$\beta$}{beta}}
\label{sec:cb_beta_dynamics}

A widespread conceptual misconception in loss re-weighting is assuming that setting the Class-Balanced Loss parameter $\beta$ close to unity (for example, $\beta = 0.9999$ in \nolinkurl{params.yaml}) implies ``weak'' or ``negligible'' balancing. In the mathematical formulation of Cui et al.~\cite{cui2019classbalanced}, the parameter dynamics operate in the exact reverse:

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Zero-Balancing Lower Limit ($\beta \to 0$):}
    \begin{equation}
      \lim_{\beta \to 0} E_{N_i} = \lim_{\beta \to 0} \frac{1 - \beta^{N_i}}{1 - \beta} = 1.0 \implies W_i = 1.0
    \end{equation}
    All classes receive identical weights regardless of empirical frequency, collapsing cleanly to standard unweighted Cross-Entropy loss.
    \item \textbf{Inverse-Frequency Upper Limit ($\beta \to 1^-$):}
    Applying L'H\^{o}pital's Rule yields:
    \begin{equation}
      \lim_{\beta \to 1^-} \frac{1 - \beta^{N_i}}{1 - \beta} = \lim_{\beta \to 1^-} \frac{-N_i \beta^{N_i - 1}}{-1} = N_i \implies W_i \propto \frac{1}{N_i}
    \end{equation}
    Class weights converge asymptotically to unconstrained inverse class frequency weighting.
\end{itemize}

Crucially, the effective number of samples $E_{N_i}$ is mathematically bounded by an asymptotic saturation ceiling:
\begin{equation}
  E_{\max} = \lim_{N_i \to \infty} E_{N_i} = \frac{1}{1 - \beta}
\end{equation}

For any candidate value of $\beta$, once the empirical observation count $N_i$ substantially exceeds $\frac{1}{1 - \beta}$, the term $\beta^{N_i} \approx 0$, causing $E_{N_i} \approx E_{\max}$ to saturate across all classes. If an engineer were to select a smaller parameter such as $\beta = 0.90$, the saturation ceiling would collapse to $E_{\max} = \frac{1}{0.10} = 10$. On biological datasets possessing $N_i \ge 100$ specimens per taxon, $\beta^{N_i} = 0.90^{100} \approx 2.6 \times 10^{-5} \approx 0$, which evaluates to $E_{N_i} = 10$ across all classes. The resulting class weights $W_i = \frac{1 - \beta}{E_{N_i}}$ become completely identical ($1.0000$), totally neutralising the balancing mechanism.

Consequently, to maintain non-saturating dynamic sensitivity across citizen-science observation frequencies ($N_i \in [50, 2000]$), $\beta$ must reside within the high-sensitivity interval $[0.99, 0.9999]$ (Table~\ref{tab:beta_comparison}).

\paragraph{Parameter Sourcing and Precedence Hierarchy.}
The value declared in \nolinkurl{params.yaml:training.cb_beta} ($0.9999$) represents the canonical literature baseline for large-scale biodiversity imagery. During automated hyperparameter optimization (\texttt{src/taxon\_vision/models/training/tuning.py}), Optuna explored the bounded interval $\beta \in [0.99, 0.9999]$ targeting validation Macro PR-AUC. The resulting Bayesian optimum converged to $\beta = 0.995927$, persisted in \nolinkurl{models/checkpoints/best_params.yaml}. In the training runner (\texttt{runner.py}), parameter resolution executes via a three-tier hierarchy: Tier~1 (active Optuna study if \texttt{--tune} is passed), Tier~2 (persisted \nolinkurl{best_params.yaml}), and Tier~3 (configuration baseline). Thus, the production model was trained under Optuna's optimal $\beta = 0.9959$, providing a calibrated $+19.7\%$ gradient boost on rare taxa without triggering inverse-frequency gradient instability.

\subsection{MLflow 3.x Interlock Architecture and Model Passports}

Whilst Optuna orchestrates the search mathematics, it inherently lacks the infrastructure to permanently archive model provenance across a distributed engineering team. MLflow bridges this gap, operating as the continuous flight data recorder for our training pipeline.

The integration is implemented directly within the objective function and the overarching DVC pipeline. The tuning session registers as an MLflow experiment on the tracking server, and each trial is executed within a nested child run. To avoid socket starvation and excessive network I/O during rapid hyperparameter sweeps, all epoch metrics -- training loss, validation loss, Top-1 accuracy, Macro F1-score, and validation Macro PR-AUC -- are aggregated in memory and submitted at trial completion or ASHA pruning using \texttt{MlflowClient().log\_batch()}. The lifecycle of the primary run is governed by a deterministic context manager, guaranteeing that unexpected execution exceptions transition the run to a \texttt{FAILED} state rather than hanging perpetually.

\subsubsection{MLflow 3.x First-Class LoggedModels and Cross-Stage Continuity}
\label{sec:mlflow3_logged_models}

Modern MLOps practice in MLflow 3.x departs from legacy path-based model registries, elevating models to first-class \texttt{LoggedModel} entities identified by an immutable identifier (\texttt{m-...}). The architecture enforces four critical tracking invariants:
\begin{enumerate}
    \item \textbf{Cross-Stage DVC Run Continuity:} Stage~4 (\nolinkurl{train.py}) initialises the parent MLflow run and serialises its unique identifier to \nolinkurl{reports/train_metrics.json:mlflow_run_id}. Rather than scattering pipeline outputs across detached runs, subsequent stages (\nolinkurl{export_onnx.py}, \nolinkurl{calibrate.py}, and \nolinkurl{evaluate.py}) re-enter this active context using the RAII context manager \nolinkurl{resume_parent_mlflow_run()}. This unifies PyTorch weights, ONNX graphs, conformal thresholds, and evaluation reports into a single, cohesive lineage record.
    \item \textbf{Four-Split Dataset Lineage (\texttt{mlflow.data}):} Every training run explicitly logs its four stratified tensor partitions (\texttt{train}, \texttt{val}, \texttt{cal}, \texttt{test}) alongside their DVC MD5 cryptographic content digests, instance counts, and DarwinCore schema tags using \nolinkurl{mlflow.log_input()}. This establishes cryptographically verifiable provenance between raw citizen-science images and deployed model weights.
    \item \textbf{Dual-Output Tensor Signatures:} During model packaging, an explicit \texttt{ModelSignature} is inferred from genuine validation batch tensors via \nolinkurl{infer_signature()}. The signature enforces type-safe schemas across dual output nodes: unnormalised logits ($\mathbb{R}^{B \times K}$) and penultimate feature embeddings ($\mathbb{R}^{B \times D}$).
    \item \textbf{Un-Gated Model Pollution Prevention:} To prevent cluttering the Model Registry with ephemeral experimental checkpoints, unit test runs and Optuna child trials are strictly forbidden from creating registered models. Model registration is restricted exclusively to the terminal evaluation stage of the canonical DVC pipeline.
\end{enumerate}

\section{Training Dynamics and Convergence Control}
\label{sec:training_dynamics}

Because the backbone is frozen and its embeddings are cached, a training epoch of the classification head reduces to a small number of matrix products. The principal risk is therefore not under-fitting but over-fitting to the rare classes of the long tail. Three mechanisms control this risk. All of them monitor the validation Macro PR-AUC, which is also the promotion metric of the registry:
\begin{enumerate}
    \item \textbf{Best-weight restoration:} The head weights of the epoch with the highest validation Macro PR-AUC are cached and restored once training has ended, so that the returned head is the best head and not merely the last one.
    \item \textbf{Early stopping:} Training terminates when the metric has not improved for five consecutive epochs.
    \item \textbf{Learning-rate reduction on plateau:} The learning rate is halved when the metric has not improved for two epochs. Since this patience is shorter than that of early stopping, the optimiser receives at least one epoch at a reduced rate before training terminates.
\end{enumerate}

As design defaults, the baseline epoch budget is set to 30 epochs and the mini-batch size is 32 for training on cached embeddings (\texttt{epochs: 30}, \texttt{batch\_size: 32} in \nolinkurl{params.yaml}). Where embeddings are extracted from images by a Vision Transformer on the GPU, a batch size of 32 images keeps the activation memory comfortably inside the budget of Section~\ref{sec:gpu_partitioning}. The feature extraction pipeline (\texttt{taxon\_vision.pipelines.extract\_features}) extracts these representations directly from AWS S3, caching them to disk for subsequent head convergence (see Section~\ref{sec:impl_status}).

\subsection{Modular Sibling Topology and Clean Code Governance}
\label{sec:sibling_training_topology}

To eliminate monolithic software decay and satisfy Rule~08 clean-code invariants, the training engine is decomposed into single-responsibility sibling modules within \nolinkurl{src/taxon_vision/models/training/}, strictly banning nested package circularities and maintaining cognitive complexity under the threshold $\mathcal{C} < 15$:
\begin{itemize}
    \item \textbf{\texttt{runner.py}:} Orchestrates the overarching training execution lifecycle, learning rate plateau scheduling, and early stopping assertions.
    \item \textbf{\texttt{loops.py}:} Implements the tight inner forward and backward training loops operating over pre-cached GPU embedding tensors without dynamic allocation overhead.
    \item \textbf{\texttt{embeddings.py}:} Manages PyTorch TensorDataset abstractions, stratified minibatch creation, and tensor shape validation.
    \item \textbf{\texttt{tuning.py}:} Encapsulates Bayesian hyperparameter objective functions, trial scoping, and ASHA pruning logic.
    \item \textbf{\texttt{tracking.py}:} Provides RAII-scoped context managers for atomic MLflow run lifecycle management, guaranteeing clean teardown upon runtime exceptions.
    \item \textbf{\texttt{checkpoint.py}:} Manages best-weight restoration and deterministic PyTorch state-dict serialisation.
    \item \textbf{\texttt{types.py}:} Enforces parameter encapsulation via frozen dataclasses (\texttt{TrainingConfig}, \texttt{TrainingMetrics}, \texttt{OptunaTrialResult}), completely eliminating untyped tuple blindness.
\end{itemize}

Data augmentation applied during embedding extraction must respect biological invariants. Horizontal reflection yields physically plausible specimens, because most organisms are bilaterally or radially symmetric about a vertical axis. Vertical reflection is prohibited: gravity and phototropism impose a canonical orientation, so that an inverted specimen would never occur in field imagery and would merely bias the learned spatial priors.
