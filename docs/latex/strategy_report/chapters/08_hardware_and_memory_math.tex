\chapter{Hardware Optimisation and Memory Mathematics}
\label{ch:hardware_math}

Operating a high-throughput machine learning service under strict latency service-level objectives (SLOs) requires moving decisively beyond theoretical model performance and addressing the physical limitations of silicon. This chapter explicitly defines the mathematical transformations utilised to compress neural network memory footprints, the formal theorems rigorously governing epistemic safety thresholds, and the memory complexity equations required to safely bound vector database consumption.

\section{Static and Dynamic Quantisation Architectures}
\label{sec:quantization_math}

Deep neural networks are fundamentally composed of dense, high-dimensional weight matrices. By default, standard training frameworks construct these matrices using 32-bit floating-point (FP32) numerical representations. Whilst FP32 provides extreme gradient precision during the backpropagation phase of training, it is highly inefficient during production inference. FP32 tensors consume vast amounts of GPU VRAM, and executing matrix multiplications at this precision severely bottlenecks memory bandwidth, thereby inflating prediction latency.

In order to optimise the deployment architecture, the PyTorch classification head and feature extractor are compiled into the Open Neural Network Exchange (ONNX) format with dual output nodes ($f(x) \in \mathbb{R}^K$, $z(x) \in \mathbb{R}^D$), cleanly decoupling the computational graph from Python's interpreter overhead. Subsequently, the ONNX Runtime applies Integer-8 (INT8) Post-Training Quantisation (PTQ). This mathematical operation maps the continuous floating-point weights and activations onto a discrete 8-bit integer grid.

The linear quantisation mapping function is formally defined as:
\begin{equation}
q = \text{clamp}\left( \text{round}\left(\frac{x}{S}\right) + Z, \, q_{\min}, \, q_{\max} \right)
\label{eq:quant_mapping}
\end{equation}
where $q \in [q_{\min}, q_{\max}]$ denotes the 8-bit quantised integer (typically $[-128, 127]$ for signed INT8 or $[0, 255]$ for unsigned uint8), $x$ represents the continuous 32-bit floating-point activation or weight value, $S \in \mathbb{R}^+$ is the positive real scale factor defining the step size between discrete quantised bins, and $Z \in \mathbb{Z}$ is the integer zero-point offset that aligns real-world mathematical zero with the discrete grid to ensure zero-padding operations remain exact.

The platform implements two distinct quantisation paradigms depending on operational context:
\begin{enumerate}
    \item \textbf{Static INT8 QDQ Quantisation with Empirical Calibration:} Static Post-Training Quantisation inserts explicit QuantizeLinear/DequantizeLinear (QDQ) operator pairs surrounding convolutional and linear layers. The dynamic range of intermediate activation tensors is calibrated empirically using a dedicated calibration dataset reader (\texttt{Taxon\-Calibration\-Data\-Reader}) streaming genuine biological image batches. For symmetric signed quantisation, the scale factor $S$ is computed using MinMax calibration:
    \begin{equation}
    S = \frac{\max\left( |x_{\min}|, \, |x_{\max}| \right)}{127}, \quad Z = 0
    \label{eq:minmax_calibration}
    \end{equation}
    Static calibration eliminates runtime scaling overhead entirely, enabling fused integer matrix multiplications on hardware accelerators.
    \item \textbf{Dynamic INT8 Quantisation with Logit Node Preservation:} In resource-constrained CPU environments lacking calibration data, dynamic quantisation quantises weights statically to INT8 whilst calculating activation scale factors dynamically at inference time. Crucially, as implemented in \nolinkurl{quantizer.py}, the terminal linear projection layers directly emitting classification logits are excluded from aggressive quantisation. Preserving FP32 precision on logit output nodes prevents rounding distortions that would otherwise perturb the delicate unnormalised activation margins required by the Helmholtz energy detector and Split Conformal Prediction.
\end{enumerate}

By mapping 32-bit floats to 8-bit integers, the model's theoretical tensor parameter footprint is deterministically reduced by $75\%$ (an exact $4:1$ bit-width ratio; for example, reducing an illustrative 400~MB model to approximately 100~MB). Because INT8 operands are significantly smaller, modern hardware can efficiently pack multiple operations into single SIMD (Single Instruction, Multiple Data) registers, strongly leveraging AVX-512 Vector Neural Network Instructions (VNNI) on CPUs or Tensor Cores on GPUs. In published deployment benchmarks across standard vision backbones, this quantisation pattern yields an empirical $2\times$ to $4\times$ latency acceleration with typically less than a $1\%$ degradation in top-1 accuracy (subject to validation on target biological splits).

\section{Marginal Coverage Guarantees in Conformal Prediction}
\label{sec:conformal_math}

Standard classification models merely output uncalibrated probability distributions. In ecological monitoring, uncalibrated deep neural networks exhibit overconfidence, frequently assigning extreme softmax probabilities to out-of-distribution or corrupted observations. Relying on raw softmax scores introduces unquantified epistemic risk into automated observation catalogues.

To eliminate this failure mode, the architecture wraps the base classifier in a Split Conformal Prediction layer. Rather than forcing the model to emit a single point prediction, conformal prediction evaluates input ambiguity and generates a dynamic \textit{set} of candidate taxa. When the input observation exhibits unambiguous morphological features, the prediction set collapses to a singleton. If the image is occluded or ambiguous, the set expands into a multi-candidate differential to preserve rigorous error guarantees.

Formally, this epistemic safety is guaranteed by the marginal coverage theorem:
\[
\mathbb{P}\left(Y_{n+1} \in \hat{C}(X_{n+1})\right) \ge 1 - \alpha,
\]
where $\mathbb{P}$ denotes the probability measure taken over the exchangeable joint distribution of images and taxonomic labels, $X_{n+1}$ represents the unseen test observation, $Y_{n+1} \in \{1, \dots, K\}$ is the unobserved true ground-truth taxonomic label, $\hat{C}(X_{n+1})$ is the dynamic prediction set systematically generated by the conformal algorithm containing zero, one, or multiple candidate taxa, and $\alpha \in (0, 1)$ is the nominal significance error tolerance (fixed at $\alpha = 0.05$ to enforce a $95\%$ marginal coverage guarantee).

This theorem provides a remarkably robust distribution-free guarantee: at least $1 - \alpha$ of future predictions are mathematically guaranteed to contain the true species within the returned prediction set, holding under exchangeability between calibration and test observations without parametric assumptions on the underlying feature distributions.

\section{Memory Complexity of Hierarchical Vector Graphs}
\label{sec:hnsw_memory}

Retrieval-augmented generation systems frequently bottleneck on disk I/O when attempting to query massive vector databases stored on solid-state drives. In order to guarantee sub-millisecond retrieval latency during the Single-Stage Metadata-Filtered HNSW traversal, the entire Reference Exemplar Catalogue must clearly fit completely within the host system's Random Access Memory (RAM).

In order to achieve this, the architecture establishes an illustrative engineering sizing model. Assuming an operational scope scaling to a design baseline of $10{,}000$ distinct taxa, with $50$ curated environmental crops per taxon, the vector index reaches a safe upper bound of $500{,}000$ nodes.

The theoretical memory lower bound $\mathcal{M}_{\text{index}}$ required to securely store the raw embedding vectors in memory is mathematically calculated as:
\[
\mathcal{M}_{\text{index}} = N_{\text{nodes}} \times D_{\text{dim}} \times B_{\text{bytes}},
\]
where $\mathcal{M}_{\text{index}}$ is the theoretical memory footprint required to store the raw embedding vectors in RAM, $N_{\text{nodes}} = 500{,}000$ is the upper bound of curated biological exemplars, $D_{\text{dim}}$ is the feature dimensionality of the chosen Vision Foundation Model, and $B_{\text{bytes}} = 4$ is the byte-size of 32-bit floating-point (FP32) numerical representations.

Whilst operational models leverage DINOv3 ($D_{\text{dim}} = 384$) or BioCLIP-2 ($D_{\text{dim}} = 512$), adopting $D_{\text{dim}} = 768$ (corresponding to large ViT architectures) establishes a conservative upper bound:
\[
\mathcal{M}_{\text{index}} = 500{,}000 \times 768 \times 4 \text{ bytes} = 1{,}536{,}000{,}000 \text{ bytes} \approx 1.536 \text{ GB}.
\]
Under this conservative assumption, the entire uncompressed vector payload occupies at most $1.536\text{ GB}$ (collapsing to $0.768\text{ GB}$ under DINOv3 or $1.024\text{ GB}$ under BioCLIP-2). Even when accounting for graph navigational links in HNSW, the complete index consumes well under $3.0\text{ GB}$ of host memory, allowing the entire retrieval graph to reside in fast DDR5 memory alongside serving workers and preserving the sub-$25\text{ ms}$ inference SLO.
