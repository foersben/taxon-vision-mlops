\chapter{Hardware Optimisation and Memory Mathematics}
\label{ch:hardware_math}

Operating a high-throughput machine learning service under strict latency service-level agreements (SLAs) requires moving decisively beyond theoretical model performance and addressing the physical limitations of silicon. This chapter explicitly defines the mathematical transformations utilised to compress neural network memory footprints, the formal theorems rigorously governing epistemic safety thresholds, and the memory complexity equations required to safely bound vector database consumption.

\section{Dynamic Quantisation and Tensor Compression}
\label{sec:quantization_math}

Deep neural networks are fundamentally composed of dense, high-dimensional weight matrices. By default, standard training frameworks construct these matrices using 32-bit floating-point (FP32) numerical representations. Whilst FP32 provides extreme gradient precision during the backpropagation phase of training, it is highly inefficient during production inference. FP32 tensors consume vast amounts of GPU VRAM, and executing matrix multiplications at this precision severely bottlenecks the memory bandwidth, thereby increasing prediction latency.

In order to optimise the deployment architecture, the PyTorch classification head and feature extractor are exported to the Open Neural Network Exchange (ONNX) format, cleanly decoupling the computational graph from Python's execution overhead. Subsequently, the ONNX Runtime strategically applies Integer-8 (INT8) static quantisation. This mathematical operation robustly maps the high-resolution continuous floating-point weights onto a discrete 8-bit integer grid. Static Post-Training Quantisation (PTQ) with a calibration dataset is strictly required for the convolutional and vision-transformer backbones, while dynamic quantization is reserved exclusively for the Vision-Language Model's linear projection layers.

The quantisation mapping function is formally defined as:
\[
q = \text{round}\left(\frac{x}{S}\right) + Z
\]
In this formulation:
\begin{itemize}
    \item $q$ represents the resulting 8-bit quantised integer representation.
    \item $x$ denotes the original 32-bit floating-point weight or activation value from the trained network.
    \item $S$ is the floating-point scale factor, which effectively defines the continuous step size between discrete quantised bins.
    \item $Z$ is the 8-bit integer zero-point offset, which aligns the real-world mathematical zero with the quantised integer zero in order to ensure zero-padding operations remain absolutely precise.
\end{itemize}

By mapping 32-bit floats to 8-bit integers, the model's theoretical tensor parameter footprint is deterministically reduced by $75\%$ (an exact $4:1$ bit-width ratio; for example, reducing an illustrative 400~MB model to approximately 100~MB). Because INT8 operands are significantly smaller, modern hardware can efficiently pack multiple operations into single SIMD (Single Instruction, Multiple Data) registers, strongly leveraging AVX-512 Vector Neural Network Instructions (VNNI) on CPUs or Tensor Cores on GPUs. In published deployment benchmarks across standard vision backbones, this quantisation pattern yields an empirical $2\times$ to $4\times$ latency acceleration with typically less than a $1\%$ degradation in top-1 accuracy (subject to validation on target biological splits).

\section{Marginal Coverage Guarantees in Conformal Prediction}
\label{sec:conformal_math}

Standard classification models merely output uncalibrated probability distributions. In a biological monitoring context, an uncalibrated model might confidently assign a $99\%$ softmax probability to a specific species of tiger, even when presented with a heavily obscured photograph of a domestic cat. Relying on these raw probability scores inevitably introduces unacceptable epistemic risk into the data pipeline.

In order to thoroughly mitigate this, the architecture securely wraps the base classifier in a Split Conformal Prediction layer. Rather than forcing the model to emit a single, highly confident -- yet potentially entirely incorrect -- point prediction, conformal prediction explicitly evaluates the input ambiguity and generates a dynamic \textit{set} of candidate taxa. If the visual input is clean and prototypical, the set cleanly collapses to a single species. If the image is blurry, occluded, or visually ambiguous, the set naturally expands (for instance, returning three visually similar sibling species) to maintain absolute mathematical safety.

Formally, this epistemic safety is guaranteed by the marginal coverage theorem:
\[
\mathbb{P}(Y_{n+1} \in \hat{C}(X_{n+1})) \ge 1 - \alpha
\]
Where:
\begin{itemize}
    \item $\mathbb{P}$ denotes the probability measure taken over the exchangeable joint distribution of images and taxonomic labels.
    \item $X_{n+1}$ represents the unseen test observation (the incoming citizen-science photograph features).
    \item $Y_{n+1}$ is the unobserved, true ground-truth taxonomic label for that test observation.
    \item $\hat{C}(X_{n+1})$ is the dynamic prediction set systematically generated by the conformal algorithm, containing zero, one, or multiple candidate taxa.
    \item $\alpha$ is the user-defined nominal significance level (error tolerance). For example, setting $\alpha = 0.05$ rigorously enforces a $95\%$ coverage guarantee.
\end{itemize}

This theorem provides a remarkably robust distribution-free guarantee. This means that exactly $1 - \alpha$ of all future predictions will correctly contain the true species within the returned set, completely regardless of the underlying data distribution, lighting conditions, or base model architecture.

\section{Memory Complexity of Hierarchical Vector Graphs}
\label{sec:hnsw_memory}

Retrieval-augmented generation systems frequently bottleneck on disk I/O when attempting to query massive vector databases stored on solid-state drives. In order to guarantee sub-millisecond retrieval latency during the Single-Stage Metadata-Filtered HNSW traversal, the entire Reference Exemplar Catalogue must clearly fit completely within the host system's Random Access Memory (RAM).

In order to achieve this, the architecture establishes an illustrative engineering sizing model. Assuming an operational scope scaling to a design baseline of $10,000$ distinct taxa, with $50$ curated environmental crops per taxon, the vector index reaches a safe upper bound of $500,000$ nodes.

The theoretical memory lower bound $\mathcal{M}_{\text{index}}$ required to securely store the raw embedding vectors in memory is mathematically calculated as:
\[
\mathcal{M}_{\text{index}} = N_{\text{nodes}} \times D_{\text{dim}} \times B_{\text{bytes}}
\]
Where:
\begin{itemize}
    \item $\mathcal{M}_{\text{index}}$ is the total theoretical memory footprint required to store the raw embedding vectors in RAM.
    \item $N_{\text{nodes}}$ is the absolute upper bound of discrete biological exemplars within the retrieval catalogue ($500,000$).
    \item $D_{\text{dim}}$ is the feature dimensionality of the chosen Vision Foundation Model. The active BioCLIP-2 backbone (a ViT-L/14 architecture) produces $768$-dimensional vectors ($z_{\text{child}} \in \mathbb{R}^{768}$); the sizing model below therefore adopts $D_{\text{dim}} = 768$ as the design value.
    \item $B_{\text{bytes}}$ is the byte-size of the numerical precision format ($4$ bytes for standard FP32).
\end{itemize}

Evaluating this expression logically yields the worst-case upper bound:
\[
\mathcal{M}_{\text{index}} = 500,000 \times 768 \times 4 \text{ bytes} = 1,536,000,000 \text{ bytes} \approx 1.536 \text{ GB}
\]
By formally proving that the uncompressed vector payload requires at most $1.536 \text{ GB}$ under the active $768$-dimensional BioCLIP-2 architecture, the system firmly guarantees that the entire HNSW graph (including navigational edge overhead) will safely consume less than $3 \text{ GB}$ of host memory. This critically allows the index to remain resident in fast RAM concurrently alongside the FastAPI worker processes, thereby completely bypassing slow hard-drive reads and successfully preserving the $25 \text{ ms}$ inference SLA.
